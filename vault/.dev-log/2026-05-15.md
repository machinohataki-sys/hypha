## What is in place now

The substrate side of the E0 success gate is fully laid down. To enumerate:

The evaluator IPC surface is wired end-to-end. The four IPCs are single-verb (`evaluator:nextInstance`, `evaluator:submitResponse`, `evaluator:f1Run`, `evaluator:irrCompute`), routed through preload bridges to a renderer-side `window.ptor.evaluator` namespace. The renderer can ask for an unrated (item, candidate) pair, submit a response, get back a typed verification envelope, and see it persisted to both `events.jsonl` and the SQLite `lesson_outcomes` table — composite-keyed `${itemId}::${candidateId}` so two candidates within one item don't collide.

The Tuple Substrate view consumes that envelope. Three columns — Instance, Response, Verdict. The verdict column renders the per-feature breakdown (each feature: its statement, its hit-or-miss flag in brass-or-oxblood), an aggregate hit-count line, and an exec-cell branch (exit code, runtime, stdout hash match) when the channel is code. Four UX states: loading skeleton, error envelope, exhausted state when no more instances remain, and a brass flash on submit-then-refetch. Cmd+Enter / Ctrl+Enter keyboard submit. A brass progress indicator at the top showing rated count over total and the current kappa.

The golden set is at the gate denominator. Thirty philosophy items spanning Aristotle through Quine, ordered against MIT OCW 24.00 and Yale OYC PHIL 181 syllabi, with canonical anchors (Bekker, Stephanus, Diels-Kranz, Adam-Tannery, Akademie-Ausgabe, A/B-pagination, SEP fallback where primary citation was uncertain). Twenty LLM-systems items spanning attention softmax, KV-cache mathematics, RoPE rotation derivation, RLHF Bradley-Terry, FlashAttention IO complexity, and the Chinchilla scaling-law. Each LLM-systems item carries an executable code cell that prints a deterministic result; expected stdout hashes were computed by running the code locally before sealing.

A Lean type-check stub sits in the verification-channels directory alongside sealed-rubric and exec-cell. The stub mirrors their interface — `lockProof` and `verifyAgainstProof` — and always returns a structured pass-false envelope with explicit reason. The toolchain probe has a two-second timeout. Module header documents the E2 swap-in path. The reason this exists at E0 is so events.jsonl can include `verification_channel: 'proof'` and the harness can dispatch to it without conditional code, even though the body of the verifier waits for E2 implementation.

The label-cli is now usable. Per-item the rater sees the three answer-features definitions and their first two alt-phrasings, so they know what to look for before reading the candidate response. Verdict confirmations come back in brass for pass and oxblood for fail, with the ANSI codes gated on whether stdout is a TTY (piped output stays clean). The progress bar reports rated and skipped counts; on full-completion resume a session summary prints before exit. Save-and-resume continues to work via the existing sidecar reader.

The cost-recording wrap is uniform across the seven executeChat dispatch sites that previously did not have it: lesson body generation, scoring, the three prosecute-judge-rewrite stages, the confession layer, and the canonical-layer syllabus extractor. Each wrap records to the SQLite `model_calls` table with a typed task label, latency, success flag, and an estimated cost computed against the placeholder per-provider rates frozen at the start of E0. The rate card is still labeled intentional-placeholder; calibrated pricing is the work of a future infrastructure system per the main blueprint.

## What the substrate does not yet say

It does not yet have a real human-rater kappa. The kappa of 0.94 on the philosophy topic comes from the D5-D10 Wolf-rater baseline against author-truth, on twelve items — a synthetic baseline, marked WOLF_RATER_BASELINE in the run output. The substrate is ready for human raters; the human raters are not yet on the substrate. That is the substance of Phase 3 (Days 19-24) and the substance of the E0 success gate. If the founder and a second rater put real labels on the fifty items and the resulting kappa lands above 0.7, the substrate is vindicated. If it lands below, the substrate is wrong in a way that is now legible — not hidden behind synthetic numbers.

It does not yet have a held-out F1 measurement that means anything for philosophy. The substring channel scored 0.083 on the D10 twelve-item run; the additional alt-phrasings in items 13-30 may or may not move that number, and it remains the case that substring matching is structurally a poor verifier for philosophical prose. The week-1 close already named this honestly. For LLM-systems items, the exec-cell channel should outperform substring by a wide margin because the verification is binary code execution; that prediction will be tested in Phase 3.

It does not yet have a calibration release. The plan calls for the first one to land in week four (Phase 4, Days 25-27) as a dry run of the E1 wk16 calibration-release format: a frozen golden snapshot, a reproduction script, a run.log of kappa and F1, and a README that documents what the numbers mean and what would falsify them. Phase 4 work is sequenced behind Phase 3 because the numbers it reports are the numbers Phase 3 measures. There is no calibration release before the measurement; there is no measurement before the rating.

## Substrate diagnostics worth noting

The fingerprint-comparison bug in the philosophy seeder was a quiet but consequential find. The R2 fix in D4 extended `_itemFingerprint` to include `phrasing_hashes`, but the comparison branch that decides whether an existing item has drifted was still joining only `claim_hash`. On every idempotent re-run, twelve items read as drifted — a false positive that would have masked real drifts. The Phase 1 batch fixed the comparison branch to call `_itemFingerprint(existing)` directly so candidate and existing use identical fingerprint logic. Two consecutive idempotent runs now report zero writes and zero drifts.

The lazy-require pattern in layer1-canonical was preserved during the cost-wrap pass. That module is designed to degrade gracefully when the LLM is unavailable — heuristic syllabus extraction still works — so the new sqlite dependency was wrapped in an inner try/catch with a console.warn on failure, matching the existing offline-resilient style. The cost ledger gets populated when LLM calls succeed; when they fail or the SQLite layer is unavailable, the syllabus pipeline still ships its result.

## Substrate constraints worth restating

A reminder against false confidence: the Wolf-rater kappa is not human inter-rater reliability. The Wolf-rater is a T4_JUDGE-class LLM rating the same items the author rated, on the same rubric, with the same alt-phrasings. High agreement there says the rubric is interpretable by an LLM. It does not say the rubric is interpretable by two independent humans. That is the next measurement, and it is the gate measurement.

The LLM-as-rater channel will not be substituted for the human channel if the second rater is unavailable. The plan locked this in answer to a user question on Phase 3 protocol; the dev-log states the same here so the lock is visible. If the second rater does not rate in Days 22-23, TRIGGER-1 fires, E0 extends. The reported kappa never silently substitutes the synthetic baseline for the human pair.
