# Dev-log — V0.5 day 1

Branch `v0.5-substrate` cut from `main` at `f8107b3`. Six months of accumulated work landed on `main` as a single baseline commit and now sits frozen until the first calibration release at week 16. Existing user course data archived under `vault/.archive-pre-v0.5/2026-05-10/` and removed from the working tree. New vault subdirectories — `.evaluator/`, `.calibration/`, `.dev-log/` — are now the only paths under `vault/` that this branch will track.

## What changed in thinking

The path through to v3.0 was reorganized around a single principle: every epoch ships one falsifiable proof, and the proof has to pass a verifier that is not a language model. The previous blueprint had measurement gates everywhere but the measurement instrument was not specified. A model judging another model's answer is correlated agreement, not verification. The substrate underneath the lesson surface needs at least one channel — runnable code, a type-checking proof, or an answer key sealed before the test — that a model cannot quietly hallucinate past.

The four-week test for epoch zero is built around that channel. Twenty tuples, single learner, two raters, fifty-item golden set with double-coded labels and inter-rater reliability κ reported before any F1 number. The target is 80% transfer-hold under the non-model channel. If that target is missed by more than ten points, the substrate is wrong and the work pauses.

## What did not change

The application shell. The four character contracts. The provider abstraction. The dispose-course gesture. The bias correction in the constitution. The anti-ingratiation post-stream scan. The 5-connector harvest layer. These continue to run as monitoring, not as the critical-path verifier. Some of them will likely be cut in week one through three; the cuts will be recorded here.

## Why publish this on day one

Trust accumulates around visible labor. A repository that goes silent for six months and then ships a polished release does worse on this dimension than a repository that publishes weekly evidence of how the question is being answered, including evidence that the answer is not yet known. The first calibration release at week 16 will include the F1 number whether or not it passes the gate. If it does not pass, the dev-log will explain why.
