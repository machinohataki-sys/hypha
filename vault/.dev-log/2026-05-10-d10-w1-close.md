## What the numbers say

The synthetic two-rater run on twelve items × three candidates × three features produced:

| metric | value | reading |
|---|---|---|
| κ (Wolf vs author truth) | 0.9419 | almost-perfect agreement on which features each candidate hit |
| F1 (substring channel vs rater majority) | 0.0833 | recall 0.04, precision 1.00 |
| candidates evaluated | 35 of 36 | one rater disagreement skipped |

Two readings of the same data:

The 0.94 number says the language-model agrees with the author on rubric application. Given the same instance, the same features list, and the same candidate response, the model marks the same feature ids the author marked. This is interesting; it is a baseline for what an LLM rater can do on a well-decomposed rubric. It is not human inter-rater reliability. The label on every artifact says so.

The 0.08 number says the substring channel cannot bridge the lexical gap between author rubric phrasings and learner prose. Even with seven alt-phrasings per feature — including morphological variants like "monistic" alongside "monism" — the channel under-detects the true positives. Twenty-two of twenty-three true-pass candidates are wrongly marked fail. The channel produces zero false alarms (precision 1.00) but its recall on philosophy prose is structurally limited.

The honest take: substring matching is suitable for closed-vocabulary domains. Code cells either run or do not; type-checked proofs either compile or do not. Philosophy is a domain where rubric and learner share intent but rarely share contiguous strings. The production verifier for philosophy is a human rater, with sealed sha256 anchoring the rubric definition. The F1 number for philosophy comes from human inter-rater majority, not from auto-vs-rater. This is the same conclusion the D4 dev-log reached; the D5-D10 enrichment of alt-phrasings did not change it.

A future patch could try tokenized overlap with a threshold rather than pure substring, or stem-based matching. Those are improvements, not corrections; the present state is honestly reported.

## What is now in place

The substrate code path:
1. The seeder writes twelve philosophy items with feature decomposition + sealed sha256 + author truth.
2. The label-cli (interactive) writes per-rater sidecar files; race condition between rater A and rater B eliminated structurally.
3. The wolf-rater (synthetic) writes rater-b sidecars via the same atomic-rename writer.
4. The golden-loader merges sidecars onto items, computes κ on per-cell binary cells.
5. The f1-harness consumes loader output, runs verifyFeatures per candidate, scores against rater majority.
6. The compute-kappa CLI gates F1 publication on κ ≥ 0.7.
7. A run-evaluation orchestrator chains the four steps and writes a dated summary to `vault/.evaluator/runs/`.

The UI kernel swap branches on `verification_channel`. Legacy chat unchanged. The Instance / Response / Verdict layout renders if the state declares a verification channel; the main.js + preload.js wiring is the next deliverable.
