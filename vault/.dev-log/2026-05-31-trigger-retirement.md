# V0.5 E0 — Trigger retirement and replacement

Per MEOW R3 audit on 2026-05-31, the V0.5 main plan's pre-committed escape triggers for EPOCH 0 must be formally retired or replaced before E1 substantive ship work begins. A pre-commitment that gets bypassed by reframing the substrate question is not a pre-commitment. This entry restores pre-commitability to the next gate.

This file is referenced by `vault/.dev-log/2026-05-31.md` as the first half of the E0 CONDITIONAL PASS 14d extension condition.

## TRIGGER-1 — retired

Original (V0.5 main plan, EPOCH 0 §Pre-committed escape triggers):
> TRIGGER-1 (substrate): wk4 IRR κ <0.6 → reset golden-set protocol, halt v0.2 work, rerun within 14d.

Reason for retirement: the substrate-thesis question was reformulated during Phase 3 D19-D20. The founder mid-rating diagnosed a structural rubric design flaw (question vocabulary echoes feature vocabulary, collapsing rating to keyword-matching). Cohen's κ on the original 50-item set would measure vocabulary-coverage agreement, not concept-understanding agreement; the κ metric became inapplicable to the substrate-thesis. The pivot to mutation-test on llm-systems exec-cell is a different question entirely, not a rater-pair κ measurement.

Replacement (binds E1 gate decision arithmetic):

**TRIGGER-1-replacement (auto-judge substrate)**: mutation-test F1 on a second exec-cell domain at 100-item scale delivered by E1-wk8 ≥ 0.85. Methodology held constant: algorithmic perturbations (semantic-preserving) and mutations (semantic-breaking) generated by `app/lib/evaluator/mutators.js` (or its E1 evolution); F1 computed by `app/scripts/run-mutation-test.js`. If F1 < 0.85 on the second domain, the substrate-thesis on code-channel does not generalize, and E1 substantive ship work pauses for substrate diagnostic.

**TRIGGER-1b-replacement (human-rater substrate, if rater channel is used in E1)**: any HUMAN-RATER F1 metric in E1 calibration release MUST be preceded by Cohen's κ ≥ 0.7 on the same eval set, computed from independent rater pair. The V0.5 main plan cross-cutting constraint #9 was always meant for this case; the constitution update at `fluffy-hugging-swan.md` makes the distinction explicit.

Reset clock: 14 days from the date E1 work begins. If TRIGGER-1-replacement is not satisfied at E1-wk8 (~56 days into E1), trigger fires honestly: pause + diagnostic.

## TRIGGER-2 — retired

Original:
> TRIGGER-2 (cost): wk4 median ¥/tuple >¥3 → reduce to T4_JUDGE class, retest within 7d.

Reason for retirement: the cost-ledger instrumentation gap (73 of 74 logged model_calls missing token metadata) rendered the median measurement unevaluatable. The headline number in `vault/.calibration/2026-05-31/run.log` (median $0.0042 USD per logged call) is computed from a sample of n=1 metered call; this is not a fair gate signal. The pre-commitment was technically not violated, because the number stayed below the threshold, but the number itself is structurally invalid.

Replacement:

**TRIGGER-2-replacement (cost-ledger instrumentation gate, blocking)**: cost-ledger token-metadata coverage on `model_calls` table must reach ≥ 95-percent by E1-wk4 (~28 days into E1). Coverage measured as: count of rows where `input_tokens IS NOT NULL AND output_tokens IS NOT NULL` divided by total rows since 2026-05-11 (gate day). If coverage <95-percent at E1-wk4, no cost-based gate decision is permitted in subsequent E1 measurements; the cost target moves to "unevaluatable, ship deferred" until instrumentation is fixed.

**TRIGGER-2b-replacement (cost target, contingent on instrumentation)**: once instrumentation reaches 95-percent coverage, the V0.5 main plan target of median ¥/tuple ≤ ¥1.5 in E1 calibration release applies as originally written. If instrumentation reaches coverage AND median exceeds ¥2.5 (V0.5 main plan TRIGGER-3 for E1), demote default capability class per the original plan.

Reset clock: 28 days into E1. Instrumentation either lands or the cost gate is acknowledged unevaluatable until it does.

## TRIGGER-3 — retired

Original:
> TRIGGER-3 (burn): founder reports >60h/wk for 2 consecutive weeks → mandatory 5-day pause.

Reason for retirement: founder burn-rate was not tracked during E0. No dev-log entry recorded hours worked per week. The pre-commitment had no instrumentation. The pivot mid-Phase-3 (rubric bug + bilingual sidecar + auto-judge build) was substantive cognitive work that almost certainly exceeded 60h/wk for the orchestration thread, but the founder's own hours are not measured and were not surfaced. This was a soft commitment without an instrumentation backbone.

Replacement:

**TRIGGER-3-replacement (lightweight burn signal)**: founder writes one line per week in `vault/.dev-log/burn-week-N.md` noting hours spent on Hypha (rough self-estimate ±5h is fine; numeric not narrative). If two consecutive weeks report >50h, trigger fires: mandatory three-day pause from new substantive ship work (existing work continues; no new feature blueprints).

This is a deliberately weaker commitment than the original (50h vs 60h, 3d vs 5d pause), because the original was unenforceable and aspirational. A weaker enforceable commitment is more honest than a stronger unenforceable one.

Reset clock: first burn-week entry due E1-wk1 (day 7 of E1).

## Constitution constraint #9 update — pending

The V0.5 main plan cross-cutting constraints section §9 originally reads:

> IRR-before-F1 rule: any F1/accuracy metric in calibration release MUST be preceded by Cohen's κ ≥ 0.7 evidence on the same eval set.

This rule was written under prose-rubric thinking. It does not anticipate auto-judge verification channels (mutation testing on algorithmic perturbations, exec-cell determinism, future Lean elaboration) where F1 can be measured without a rater pair. The pivot to mutation-test surfaced this latent inconsistency.

The update lands in `C:\Users\32043\.claude\plans\fluffy-hugging-swan.md` cross-cutting constraints section as a separate edit. The replacement text:

> §9 IRR-before-F1 rule (revised 2026-05-31): every F1/accuracy metric in calibration release MUST be classified as one of two channel types and gated accordingly. HUMAN-RATER F1 (where ground truth comes from at least one human rater) MUST be preceded by Cohen's κ ≥ 0.7 evidence on the same eval set, computed from independent rater pair. AUTO-JUDGE F1 (where ground truth comes from a deterministic, rater-free verifier: exec-cell hash, Lean elaboration, mutation-test transform family) MUST be preceded by a channel-validity check appropriate to the verifier — for mutation-test, the validity check is publication of perturbation/mutation transform definitions in the calibration release `mutators.js` source file so external reviewers can audit the transform family. κ is N/A by category for AUTO-JUDGE channels; the gate is whether the verifier's behaviour can be independently reproduced from the published transform definitions.
