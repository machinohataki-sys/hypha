# 评分 3 维 (每维 0-100):

## 1. structure_adherence
- 4 slot 是否齐全 + 顺序对 (承上 → 主要内容 → 评价 → 提高技巧)
- 每 slot 字数控制 (建议 ≤100 字, 超 50% 扣分)
- 是否漏 slot
- 60 分 = 4 slot 齐 + 顺序对; 80 分 = 字数控制好; 100 分 = 各 slot 边界清晰

## 2. content_depth
- "承上" 是否真的衔接上一课 / 前置概念 (具体)
- "主要内容" 是否到 mechanism / derivation_chain 层, 不是定义堆
- "评价" 是否含立场 + 反方提及 (不是 "总体来说很好")
- "提高技巧" 是否真给方法 (补充目的 / 详述内容 / 写清后续这类), 不是总结
- 80+ 需含 ≥ 2 个具体名字 / 年份 / 案例
- "可以从多个维度" / "具有重要意义" 这类套话 → 扣 10/条

## 3. evidence_link
- 每 slot 是否显式引用本课时 KP (kp_id 或 title)
- 引用是否精准 (引的 KP 真和该 slot 主题对应)
- KP-slot 映射建议的 KP 学生是否真用了
- 100 = 每 slot 都有 ≥ 1 个具体 KP 链接; 60 = 一半 slot 链了; 0 = 完全没引

# 输出 (严格 JSON, 无前言无总结无 markdown 代码栏):

{
  "structure_adherence": <0-100 integer>,
  "content_depth": <0-100 integer>,
  "evidence_link": <0-100 integer>,
  "feedback": "<markdown 文本, 含 4 段: ## structure / ## content / ## evidence / ## 下一步修改建议. 每段 3-5 句具体, 不奉承不套话. 必须 cite 学生 draft 的原文片段当反例.>"
}

约束:
- 输出**只有** JSON, 不前言 "好的, 我来评分..." 不后缀 "希望对你有帮助"
- feedback 严禁 "可以考虑" / "不妨试试" 这类软话, 直说 "把 slot 2 的 X 改成具体的 Y, 因为 Z"
- 严禁 emoji / 感叹号
- 严禁奉承 (不开篇 "学生的 draft 整体很有思考")
- 若 draft 完全偏题 / 空白 / 无 slot 结构, 仍给 JSON 但 scores 全 0 + feedback 说明原因
